(1) 用語説明
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
本ドキュメントでしようする用語を定義する．

■AKTM(Automotive Kernel Traceability Manager)
  本仕様カバレッジ測定ツールの名称．

■仕様ID
  仕様を区別するための仕様番号．以下の仕様番号に分かれている．
  ・COSxxx
  ・OSxxx
  ・NOSxxx
  ・IOSxxx
  ・DOSxxx

■除外仕様ID
  対象外のSC(スケーラビリティクラス)，概念の説明や補足事項，未対応の項
  目に付与されている仕様ID．

■対象仕様ID
  テスト対象となる仕様ID．
  全仕様IDから除外仕様IDを除いたものが対象仕様IDとなる．

■TESRYデータ
  TESRY記法によって記述されたYAML形式のテストシナリオ．
  テスト対象となる仕様IDが含まれている．

■TCS
  TestCaseSheetの略．
  組み合わせテストケースの記載部分と，TESRYデータ生成のための結果内容
  部分からなる．

■TCSレコード
  TCSの1レコード．1テストケースの情報が含まれている．

(2) AKTM概要
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

(2.1) AKTMの構成
―――――――――――――――――――――――――――――――――――
AKTMのフォルダ構成とファイル構成は以下である．

aktm/
	aktm.sh								AKTM実行ファイル
	common.sh							AKTM全処理共通情報ファイル
	grep_specid_tcs.sh					[1]仕様ID毎にTCS内からgrepするスクリプト
	user.txt							AKTMユーザーズマニュアル(本ファイル)
	menu/								各メニューの実行ファイルを格納するフォルダ
		Common.rb						各メニュー処理共通情報ファイル
		SpecCoverage.rb					仕様カバレッジ測定ファイル
		InvalidSpecId.rb				不正な仕様IDチェックファイル
		UntestedSpecId.rb				テスト未実施の仕様IDチェックファイル
		TargetIdTcs.rb					対象テストケースのTCSレコード取得ファイル
		TargetIdTesry.rb				対象のテストID取得ファイル
		CheckAkc2y.rb					AKC2Y処理のチェックファイル
	result/								結果として作成したファイルを格納するフォルダ
		target_id_tcs.csv				[a]仕様IDに該当するテストケース(TCS)一覧
		target_id_tesry.txt				[b]仕様IDに該当するテストID一覧
		tesry_invalid_id.txt			[c]TESRYに含まれている不要な仕様ID一覧
	spec_id/							仕様ID一覧ファイルを格納するフォルダ
		GetSpecificationIDfromWord.rb	[2]外部仕様書から仕様IDを取り出すスクリプト
		GetSpecificationIDfromPdf.rb	[3]AUTSAR仕様書から仕様IDを取り出すスクリプト
		ngka_spec_desc.xls				区分した仕様一覧表
		data/
			ngka_spec_id.txt			[A] [2]から作成される仕様ID一覧ファイル
			ngka_spec_desc.txt			[B] [2]から作成される仕様一覧ファイル
			autosar_spec_id.txt			[C] [3]から作成される仕様ID一覧ファイル
			autosar_spec_desc.txt		[D] [3]から作成される仕様一覧ファイル
			atk2_exclusion_id.txt		[E] 対象外の仕様ID一覧ファイル
			target_id_tcs.txt			[F] TCSファイルから取得したい仕様ID一覧ファイル
	result2/							[1]で生成されるフォルダ，[1]で生成されたcsvファイルを格納する

※resultフォルダ内のファイルは，選択したメニューによって作成されるファ
  イルが異なる．詳細は，(3)(4)章を参照する．
※フォルダやファイルの説明の前に付与した[*]は，他の章で説明するフォルダ
  やファイルと関連付けるためのタグである．
  [1]のTCSをgrepするツールについては，(8)章を参照する．
  [2][3][4]の仕様ID取得ツールについては，(5)(6)(7)章を参照する．

(3.1.1) 仕様カバレッジ測定
----------------------------------------------------------------------
《目的》
全仕様IDのうち，作成したテストケースで網羅される仕様IDの比率を算出して，
テストの仕様カバレッジを求める．

《処理内容》
全仕様ID一覧ファイル[A]と，対象外仕様ID一覧ファイル[E]から対象となる仕
様IDを求め，その対象仕様IDとTESRYデータに記述されている仕様IDから仕様カ
バレッジを測定する．

《結果出力方法》
全仕様IDの数，除外仕様IDの数，対象仕様IDの数，TESRYの仕様IDの数，カバレ
ッジ結果を画面に出力する．

  ===========================================
  All Spec IDs       : ***
  Exclusion Spec IDs : ***
  Target Spec IDs    : ***
  TESRY Spec IDs     : ***
  ===========================================
  Coverage           : *** %

----------------------------------------------------------------------
(3.1.2) 不正な仕様IDの存在チェック
----------------------------------------------------------------------
《目的》
TESRYデータに，除外仕様IDや存在しない仕様IDが含まれていないかを確認して，
誤記などを検出する．

《処理内容》
対象外仕様ID一覧ファイル[E]の除外仕様IDが，TESRYデータに含まれていない
かを確認する．また，全仕様ID一覧ファイル[A]に存在しない仕様IDが，TESRY
データに含まれていないかを確認する．

《結果出力方法》
1. 不正な仕様IDがTESRYに含まれていない場合は，含まれていなかったことを
   画面に表示する．

    ===========================================
    Check invalid SpecIDs
    ===========================================
    No invalid SpecID in TESRYs
    -------------------------------------------

2. 不正な仕様IDがTESRYに含まれていた場合は，TESRYに含まれていた不正な仕
   様IDを一覧にし，TESRYに含まれている不要な仕様ID一覧[c]ファイルを作成
   する．ファイルを作成したことを画面に表示する．

    ===========================================
    Check invalid SpecIDs
    ===========================================
    Check tesry_invalid_id.txt
    -------------------------------------------

----------------------------------------------------------------------
(3.1.3) テスト未実施の仕様IDチェック
----------------------------------------------------------------------
《目的》
全仕様IDのうち，作成したテストケースで網羅されていない仕様IDを確認する．

《処理内容》
全仕様ID一覧ファイル[A]と，対象外仕様ID一覧ファイル[E]から対象となる仕
様IDを求め，その対象仕様IDのうち，TESRYデータに記述されていない仕様IDを
抽出する．

《結果出力方法》
1. 網羅されていない仕様IDがない場合は，対象の仕様IDがないことを画面に表
   示する．

    ===========================================
    Check untested SpecIDs
    ===========================================
    No untested SpecIDs
    -------------------------------------------

2. 網羅されていない仕様IDがある場合，対象の仕様IDの一覧を画面に表示する．

    ===========================================
    Check untested SpecIDs
    ===========================================
    COS****
    COS****
    OS***
    NOS***
    ・
    ・
    ・
    -------------------------------------------

----------------------------------------------------------------------
(3.1.4) 仕様IDから，対象テストケースのTCSレコードを取得する
----------------------------------------------------------------------
《目的》
指定した仕様IDをテストしているテストケースの一覧を作成する．

《処理内容》
指定した仕様IDが含まれているテストケースをTCSから取得する．
仕様IDの指定方法は，1件を入力するか，仕様一覧ファイル[F]を読み込む．

《結果出力方法》
TCSから取得した指定した仕様IDが含まれているテストケースを一覧にし，CSV
ファイル[a]を作成する．ファイルを作成したことを画面に表示する．

 ===========================================
 Get TCS records that correspond to a SpecID
 ===========================================
 Check target_id_tcs.csv
 -------------------------------------------

作成するCSVファイル[a]の内容は，TCSの1行目にある項目の情報を記載する．
但し，TESRY_paramの情報は必要がない為，削除する．また，システムサービス
間に，空行を入れ，システムサービス毎に分ける．

----------------------------------------------------------------------
(3.1.5) 仕様IDから，対象のテストIDを取得する
----------------------------------------------------------------------
《目的》
指定した仕様IDをテストしているテストIDを作成する．

《処理内容》
指定した仕様IDが含まれているテストIDをTCSから取得する．

《結果出力方法》
該当する仕様IDを含むTESRYのテストIDを一覧にし，テストID一覧ファイル[b]
を作成する．ファイルを作成したことを画面に表示する．

 ===========================================
 Get TESRY that corresponds to SpecId
 ===========================================
 Check target_id_tesry.txt
 -------------------------------------------

----------------------------------------------------------------------
(3.1.6) AKC2Y処理のチェック (必要性については疑問)
----------------------------------------------------------------------
《目的》
AKC2Yで生成したTESRYデータと，生成元のTCSの整合性をチェックする．

《処理内容》
TESRYデータの件数とTCSの行数(テストケースの件数)を，システムサービスご
とに比較し，差分がないことを確認する．

《結果出力方法》
 1. TESRYデータの件数とTCSの行数(テストケースの件数)に差分がない場合は，
    差分がないことを画面に表示する．
 
    ===========================================
    Check AKC2Y
    ===========================================
    No Difference between TESRYs and TCSs
    -------------------------------------------

 2. TESRYデータの件数とTCSの行数(テストケースの件数)に差分がある場合は，
    差分があることとどちらが何件多いかを表示する．

    ========================================================
    Check AKC2Y
    ========================================================
    Difference detected
    TESRY(orTCS) has *** more/less case(s) than TCS(orTSERY)
    --------------------------------------------------------
    (***は，件数)

(4) AKTMの実行方法
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
例として，仕様カバレッジ測定を選択した場合の動作方法を挙げる．

 1. スケーラビリティクラスを指定する．
    menu/Common.rbのSCALABILITY_CLASSの値を指定したいスケーラビリティク
    ラスに変更する(指定可能："sc1"，"sc3")

    # スケーラビリティクラス
    SCALABILITY_CLASS = "sc1"

 2. AKTMを実行する．

    # cd aktsp/tools/aktm
    # ./aktm.sh

 3. 画面にメニュー一覧が表示される．
    メニューを選び，該当する英数字を入力し，Eneterキーを押す．

    ===========================================
    AKTM main menu
    ===========================================
    1: Specifications Coverage
    2: Check invalid SpecIDs
    3: Check untested SpecIDs
    4: Get TCS records that correspond to a SpecID
    5: Get TestIDs that correspond to a SpecID
    6: Check AKC2Y
    q: Quit
    -------------------------------------------
    Please input menu no:1

 4. 対象となるTESRY(もしくはTCS)のファイルを読み込む．
    読み込み中は，読み込みの進捗が表示される．

 5. 結果が出力される．

    ===========================================
    All Spec IDs       : ***
    Exclusion Spec IDs : ***
    Target Spec IDs    : ***
    TESRY Spec IDs     : ***
    ===========================================
    Coverage           : *** %

 6. 自動的にメニューの画面に戻る．
    終了する場合は，「q」を入力し，Enterキーを押すと終了する．

ルスクリプトで実行する，AKTMとは別の仕様ID毎にTCS内から該当するTCSレコ
ードをgrepするツール．
[F]の仕様ID毎に，仕様IDが該当したTCSレコードをまとめたcsvファイルを生成
する．

----------------------------------------------------------------------
(7.2) 実行方法
----------------------------------------------------------------------
 1. 実行する．
    # cd aktsp/tools/aktm
    # ./grep_specid_tcs.sh

 2. フォルダが生成され，そのフォルダ内にcsvファイルが生成される．
    ・aktsp/tools/aktm/result2
    ・***.csv (***は仕様ID)
