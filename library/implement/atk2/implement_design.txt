(1) はじめに
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

ログ出力API,状態確認API，全割込み禁止状態取得APIは，テスト対象とするOS
の実装にあわせて作成する必要がある．本ドキュメントは，次世代車載システ
ム向けRTOS(ATK2)用の，ログ出力API,状態確認API，全割込み禁止状態取得API
などの設計仕様についてまとめたものである．

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
(2) ログ出力API設計
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

・ログ出力APIは，書式指定子の数によって4つのAPIに分かれている．この書式
  指定子の数に合わせて，include/t_syslog.hで宣言されているログ出力の関
  数マクロsyslog_0，syslog_1，syslog_2，syslog_3を使用し，ログを出力す
  る
・ログ出力の関数マクロの引数に重要度prioがある．この重要度は，ログの種
  類を表すためのものであるが，今回はLOG_NOTICEに固定とする
・ログ出力APIの引数のformat，arg1，arg2，arg3をログ出力の関数マクロの
  引数として渡す

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
(3) エラー処理API
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

条件チェックのエラー処理，エラーコードチェックのエラー処理共に，ログ出
力関数AktspOutputLog_3を用いて，引数に与えられた内容を表示する．その後，
グローバル変数cp_stateにAK_FALSEを代入し，AktspShutdownOS()を発行する．

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
(4) 状態確認API設計
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

実装方法により，ATK2では確認できる項目とできない項目がある．
本章では，各APIが確認できる項目，できない項目を示す．また，確認できる項
目についてはどの情報を参照すればよいかを示す．

----------------------------------------------------------------------
(4.1) 共通設計
----------------------------------------------------------------------

・ATK2で参照できない情報は，確認を行わず，E_OKを返す
・確認した項目がエラーの場合は，エラーメッセージを出力する
  (例)タスクのタスク状態がエラーの場合
 「## Task tstat Error!! OS : 0, TESRY : 2.」
  OSの後の値は，OSオブジェクトの内部状態の値．TESRYの後の値は，TESRYで
  指定している値を出力する

----------------------------------------------------------------------
(4.2) タスク
----------------------------------------------------------------------

【タスク情報の構造体】
 ・引数のTaskIDを元に，Os_Lcfg.cで宣言されている
     タスク初期化の為のメモリ領域 TINIB
     タスク管理の為のメモリ領域   TCB
   の該当する要素を参照する(参考:kernel/task.h)
 ・引数のTaskInfoの各メンバーについて，どの情報を参照すればよいかは以下
   の通り

    AktspTaskInfoのメンバー | 参照元                           | 備考
   ========================================================================
    tm_tstat                | TCB   : TaskStateType tstat      |
   ------------------------------------------------------------------------
    tm_curpri               | TCB   : PriorityType curpri      | ※1
   ------------------------------------------------------------------------
    tm_inipri               | TINIB : PriorityType inipri      |
   ------------------------------------------------------------------------
    tm_ttype                |                                  | ※2
   ------------------------------------------------------------------------
    tm_maxact               | TINIB : uint8 maxact             |
   ------------------------------------------------------------------------
    tm_spolicy              | TCB   : PriorityType exepri      | ※3
   ------------------------------------------------------------------------
    tm_waievt               | TCB   : EventMaskType waievt     |
   ------------------------------------------------------------------------
    tm_curevt               | TCB   : EventMaskType curevt     |
   ------------------------------------------------------------------------
    tm_actcnt               | TCB   : uint8 actcnt             |
   ------------------------------------------------------------------------
    tm_porder               |                                  | ※4 ※5
   ------------------------------------------------------------------------
    tm_getrescount          |                                  | ※6
   ------------------------------------------------------------------------
    tm_osap                 | TINIB : OSAPINIB *p_osapinib     | ※7
   ------------------------------------------------------------------------
    tm_stksz                | TINIB : SizeType stksz  (SC1,SC2)| ※8 ※11
                            |         SizeType ustksz (SC3,SC4)|
   ------------------------------------------------------------------------
    tm_stk                  | TINIB : void *p_stk (SC1,SC2)    | ※9 ※11
                            |         void *ustk  (SC3,SC4)    |
   ------------------------------------------------------------------------
    tm_sstksz               | TINIB : SizeType sstksz          | ※10 ※11
   ------------------------------------------------------------------------
    tm_sstk                 | TINIB : void *sstk               | ※10 ※11
   ------------------------------------------------------------------------
    tm_coreid               |                                  |

   ※1  設定されたスケジューリングポリシがノンプリエンティブかつタスク状
        態が実行中の場合，curpriが設定した優先度から最高優先度(0)となり，
        設定した値が正かどうかの確認が出来ないため，確認を行わないが，
        OSオブジェクトの内部のcurpriが最高優先度(0)に変化したかの確認は
        行う
   ※2  TaskIDが拡張タスク数tnum_exttask(参考:kernel/task.h)未満であれば
        拡張タスク，それ以外の場合は，基本タスクとなる
   ※3  設定されたスケジューリングポリシがノンプリエンプティブの場合の
        み確認が可能である．確認方法は，ノンプリエンプティブの場合は，
        exepriが0(最高優先度)で正となる
   ※4  kernel/task.cで宣言されている，QUEUE ready_queue[TNUM_TPRI];から
        該当するタスクを検索する．このキューの要素は QUEUE型の変数へのポ
        インタであるが，TCB型(タスク管理の為のメモリ領域)の最初のメンバ
        ーであるので，TCB*へキャストし，そこからタスクIDを取得し，確認す
        る
   ※5  プレタスクフック，ポストタスクフックから確認を行う場合は，[テス
        トプログラムで指定された値]，もしくは[テストプログラムで指定され
        た値-1]と一致するかを確認する
   ※6  タスク管理の為のメモリ領域TCBの最後に獲得したリソースlastresから
        獲得中のリソース数を求め，確認する
   ※7  *p_osapからOSアプリケーションIDを求め，確認する
   ※8  信頼OSアプリケーションに所属するタスクの場合，スタックサイズとシ
        ステムスタックサイズの合計値をスタックサイズとして確認を行う
   ※9  信頼OSアプリケーションに所属するタスクの場合，システムスタック領
        域を使用するため，ustkを参照する．また，stkがNULLの場合は，コン
        フィギュレータが任意のアドレスを設定し，ATK2では参照できないため，
        確認を行わない
   ※10 非信頼OSアプリケーションに所属するタスクの場合のみ確認を行う．
        また，sstkがNULLの場合は，コンフィギュレータが任意のアドレスを
        設定し，ATK2では参照できないため，確認を行わない
   ※11 USE_TSKINICTXBがマクロ定義されていない場合のみ確認を行う

(4.3) タスクとリソースの関連づけ
----------------------------------------------------------------------

ATK2では，タスクに関連づけされたリソースは，参照できない情報である．

----------------------------------------------------------------------
(4.4) タスクとイベントの関連づけ
----------------------------------------------------------------------

ATK2では，タスクに関連づけされたイベントは，参照できない情報である．

----------------------------------------------------------------------
(4.5) タスクの占有リソース(内部リソース以外)
----------------------------------------------------------------------

引数のIndexで指定した順番に獲得したリソースIDは，内部関数の
AktspGetOrderedResourceId((4.42)参照)内で，引数のResIDと一致するか確認
する．
内部関数AktspGetOrderedResourceIdへ渡す引数は，以下の通り．
第1引数：タスク管理の為のメモリ領域p_lastrescb(引数のTaskIDを使い，取得する)
第2引数：引数のIndex
第3引数：引数のResID

----------------------------------------------------------------------
(4.6) タスクの獲得中内部リソース
----------------------------------------------------------------------

ATK2では，タスクの獲得中内部リソースは，参照できない情報である．

----------------------------------------------------------------------
(4.7) タスクにアクセス可能な非信頼OSアプリケーション
----------------------------------------------------------------------

・引数のTaskID,OsapIDを元に，Os_Lcfg.cで宣言されている
    タスク初期化の為のメモリ領域             TINIB   (参考:kernel/task.h)
    OSアプリケーション初期化の為のメモリ領域 OSAPINIB(参考:kernel/osap.h)
  の該当する要素を参照する
・OsapIDの属性が非信頼OSアプリケーションかつ，OsapIDの非信頼OSアプリケ
  ーションのビットパターンがTaskIDのアクセス許可OSアプリケーションビッ
  トマップに含まれているかを確認する

----------------------------------------------------------------------
(4.8) タスクのアプリケーションモード
----------------------------------------------------------------------

・引数のTaskIDを元に，Os_Lcfg.cで宣言されている
    タスク初期化の為のメモリ領域             TINIB   (参考:kernel/task.h)
  の起動するモードautoactに引数のModeが含まれているかを確認する

----------------------------------------------------------------------
(4.9) リソース
----------------------------------------------------------------------

【リソース情報の構造体】
 ・引数のResIDを元に，Os_Lcfg.cで宣言されている
     リソース初期化の為のメモリ領域 RESINIB
     リソース管理の為のメモリ領域   RESCB
   の該当する要素を参照する(参考:kernel/resource.h)
 ・引数のResInfoの各メンバーについて，リソース管理の為のメモリ領域のど
   の情報を参照すればよいかは以下の通り

    AktspResourceInfoのメンバー | 参照元                    | 備考
   ================================================================
    rm_resprop                  |                           | ※1
   ----------------------------------------------------------------
    rm_linkres                  |                           | ※2
   ----------------------------------------------------------------
    rm_lockflg                  | RESCB   : boolean lockflg | ※3

 ※1 ResIDが内部リソースを除くリソース数tnum_stdresource(参考:kernel/ 
     resource.h)以上であれば内部リソースと判断できるため，確認が可能で
     あるが，内部リソース以外は判断できないため，確認を行わない
 ※2 ATK2では，参照できない情報である
 ※3 ATK2では，リソースの種別がAK_INTERNAL(内部リソース)の場合，リソー
     ス管理ブロック(RESCB，RESINIB)を持たないため，リソースの種別が
     AK_INTERNALの場合は確認を行わない

----------------------------------------------------------------------
(4.10) リソースにアクセス可能な非信頼OSアプリケーション
----------------------------------------------------------------------

・引数のResID,OsapIDを元に，Os_Lcfg.cで宣言されている
    リソース初期化の為のメモリ領域           RESINIB (参考:kernel/resource.h)
    OSアプリケーション初期化の為のメモリ領域 OSAPINIB(参考:kernel/osap.h)
  の該当する要素を参照する
・OsapIDの属性が非信頼OSアプリケーションかつ，OsapIDの非信頼OSアプリケ
  ーションのビットパターンがResIDのアクセス許可OSアプリケーションビッ
  トマップに含まれているかを確認する
・ATK2では，リソースの種別がAK_INTERNAL(内部リソース)の場合，リソース管
  理ブロック(RESINIB)を持たないため，リソース種別がAK_INTERNALの場合は
  確認を行わない

----------------------------------------------------------------------

   の通り

    AktspISRInfoのメンバー | 参照元                              | 備考
   ======================================================================
    im_intno               | INTINIB : InterruptNumberType intno |
   ----------------------------------------------------------------------
    im_intatr              | INTINIB : AttributeType intatr      |
   ----------------------------------------------------------------------
    im_iniintpri           |                                     | ※1
   ----------------------------------------------------------------------
    im_curintpri           |                                     | ※2
   ----------------------------------------------------------------------
    im_istat               |                                     | ※1
   ----------------------------------------------------------------------
    im_rtnstat             |                                     | ※3
   ----------------------------------------------------------------------
    im_getrescount         |                                     | ※2
   ----------------------------------------------------------------------
    im_osap                |                                     | ※1
   ----------------------------------------------------------------------
    im_istksz              |                                     | ※1
   ----------------------------------------------------------------------
    im_coreid              |                                     |

   ※1 ATK2では，参照できない情報である
   ※2 カテゴリ2ISR情報の構造体と共通して使用しており，このパラメータは，
       カテゴリ1ISRでは使用しないパラメータであるため，確認を行わない
   ※3 ATK2では，参照できない情報であるが，AKTGが出力するテストプログラ

       ことの確認を行っている

(4.12) カテゴリ2ISR
----------------------------------------------------------------------

【カテゴリ2ISR情報の構造体】
 ・引数のISRIDを元に，Os_Lcfg.cで宣言されている
     ISR2の初期化の為のメモリ領域           ISRINIB
     ISR2の管理の為のメモリ領域             ISRCB
     割込み要求ライン初期化の為のメモリ領域 INTINIB
   の該当する要素を参照する(参考:kernel/interrupt.h)
 ・引数のISRInfoの各メンバーについて，どの情報を参照すればよいかは以下
   の通り

    AktspISRInfoのメンバー | 参照元                              | 備考
   ======================================================================
    im_intno               | ISRINIB : InterruptNumberType intno | ※1
                           | INTINIB : InterruptNumberType intno | ※2
   ----------------------------------------------------------------------
    im_intatr              | INTINIB : AttributeType intatr      | ※2
   ----------------------------------------------------------------------
    im_iniintpri           | ISRINIB : PriorityType intpri       |
   ----------------------------------------------------------------------
    im_curintpri           |                                     | ※6
   ----------------------------------------------------------------------
    im_istat               |                                     | ※3
   ----------------------------------------------------------------------
    im_rtnstat             |                                     | ※4
   ----------------------------------------------------------------------
    im_getrescount         |                                     | ※5
   ----------------------------------------------------------------------
    im_osap                | ISRINIB : OSAPINIB *p_osapinib      | ※7
   ----------------------------------------------------------------------
    im_istksz              | ISRINIB : SizeType stksz            | ※8
   ----------------------------------------------------------------------
    im_coreid              |                                     |

   ※1 スケーラビリティクラスがSC3，SC4の場合，参照が可能なため確認する
   ※2 INTINIBの情報は，C1ISRの状態確認APIを使用し，確認する
   ※3 ATK2では，参照できない情報である
   ※4 ATK2では，参照できない情報であるが，AKTGが出力するテストプログラ
       ム内にて，チェックポイントを通過することで該当するISRが動作する
       ことの確認を行っている
   ※5 ISR2管理の為のメモリ領域ISRCBの最後に獲得したリソースlastresから
       獲得中のリソース数を求め，確認する
   ※6 im_getrescountが1以上だった場合，そのときの割込み優先度マスク
       (x_get_ipm()で取得)と一致するかを確認し，im_getrescountが0の場合
       は，確認を行わない
   ※7 *p_osapinibからOSアプリケーションIDを求め，確認する
   ※8 ATK2では，機能レベル1，2の場合，参照できない情報であるため，機能
       レベル1，もしくは2の場合は確認を行わない

(4.13) カテゴリ2ISRとリソースの関連づけ

----------------------------------------------------------------------
(4.16) 割込み禁止状態
----------------------------------------------------------------------

【割込み禁止状態情報の構造体】
  引数のIntStateInfoの各メンバーについて，どの情報を参照すればよいかは
  以下の通り．

   AktspIntStateInfoのメンバー | 参照元           | 備考
  ==========================================================
   ism_disallint               | callevel_stat    | ※1
  ----------------------------------------------------------
   ism_susallint               | callevel_stat    | ※1
  ----------------------------------------------------------
   ism_susosint                | callevel_stat    | ※1
  ----------------------------------------------------------
   ism_susallcnt               | sus_all_cnt      | ※2

AktspGetOrderedSpinlockId((4.43)参照)内で，引数のSpnIDと一致するか確認
する．
内部関数AktspGetOrderedSpinlockIdへ渡す引数は，以下の通り．
第1引数：ISR2の管理の為のメモリ領域のp_lastspncb(引数のISRIDを使い，取得する)
第2引数：引数のIndex
第3引数：引数のSpnID

----------------------------------------------------------------------
(4.42) [内部関数]指定した順番に獲得したリソースID取得
----------------------------------------------------------------------

【プロトタイプ】
  StatusType AktspGetOrderedResourceId
  (RESCB* p_lastres, uint32 Index, ResourceType ResID)

【引数】
  p_lastres : 最後に獲得したリソース管理の為のメモリ領域へのポインタ
  Index     : リソースの獲得した順番
  ResID     : 確認対象の獲得中リソースID

【戻り値】
  E_OK     : 正常終了
  E_NOT_OK : 異常終了

【仕様】
  Indexで指定した順番に獲得したリソースのリソース管理の為のメモリ領域と
  引数のResIDから取得したリソース管理の為のメモリ領域が一致した場合，
  E_OKを返す．
  以下の場合はE_NOT_OKを返す．
  ・Indexが獲得中リソース総数より大きい

【リソースID確認方法】
  引数のp_lastresからリソース管理の為のメモリ領域のp_prevrescbを<獲得中
  リソース総数-Index+1>分さかのぼり，Indexに獲得したリソースのリソース
  管理の為のメモリ領域と一致するかを確認する．

----------------------------------------------------------------------
(4.43) [内部関数]指定した順番に獲得したスピンロックID取得
----------------------------------------------------------------------

【プロトタイプ】
  StatusType AktspGetOrderedSpinlockId
  (SPNCB* p_lastspn, uint32 Index, SpinlockIdType SpnID)

【引数】
  p_lastspn : 最後に獲得したスピンロック管理の為のメモリ領域へのポインタ
  Index     : リソースの獲得した順番
  SpnID     : 確認対象の獲得中スピンロックID

【戻り値】
  E_OK     : 正常終了
  E_NOT_OK : 異常終了

【仕様】
  Indexで指定した順番に獲得したスピンロックのスピンロック管理の為のメモ
  リ領域と引数のSpnIDから取得したスピンロック管理の為のメモリ領域が一致
  した場合，E_OKを返す．
  以下の場合はE_NOT_OKを返す．
  ・Indexが獲得中リソース総数より大きい

【スピンロックID確認方法】
  引数のp_lastspnからリソース管理の為のメモリ領域のp_prevrescbを<獲得中
  スピンロック総数-Index+1>分さかのぼり，Indexに獲得したスピンロックの
  スピンロック管理の為のメモリ領域と一致するかを確認する．

(5) 全割込み禁止状態取得API設計

(7.5) 異常時シャットダウン用信頼関数
―――――――――――――――――――――――――――――――――――

【プロトタイプ】
TRUSTEDFUNCTION(TRUSTED_AktspTfnShutdownOS, FunctionIndex, FunctionParams)

FunctionParamsに格納されたErrorを終了要因のエラーコードとして，
ShutdownOSを発行する．

―――――――――――――――――――――――――――――――――――
(7.6) 異常時シャットダウン用信頼関数へのラッパー関数
―――――――――――――――――――――――――――――――――――

まず，割込み禁止状態であった場合は，割込み許可状態に戻す．割込み許可状
態に戻すために参照する変数と，発行するシステムサービスは以下の通り．

・kernel/osctl_manage.cで宣言されている外部変数callevel_statを参照し，
  callevel_statがTSYS_DISALLINTと一致している場合は，
  EnableAllInterruptsを発行する
・kernel/interrupt.cで宣言されている外部変数sus_all_cntを参照し，
  sus_all_cntが1以上である場合は，sus_all_cntが0になるまで
  ResumeAllInterruptsを発行する
・kernel/interrupt.cで宣言されている外部変数sus_os_cntを参照し，
  sus_os_cntが1以上である場合は，sus_os_cntが0になるまで
  ResumeOSInterruptsを発行する

割込み禁止状態を解除した後，引数のErrorをAktspTfParamのErrorに代入し，
それをCallTrustedFunctionの第2引数として，信頼関数AktspTfnShutdownOSを
呼出す．
