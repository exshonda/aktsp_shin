(1) はじめに
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

AKTGが生成するテストプログラムを実行させるためには，割込みの発生やプロ
テクションフックの起動，ハードウェアカウンタの操作などが必要である．こ
れらを実現するために必要な関数は以下である．
・割込み発生関数
・プロテクションフック起動関数
・ハードウェアカウンタ操作関数
・スタックオーバーフロー発生関数
・CPU例外検出関数
・メモリアクセス関数
これらの関数は，ターゲット毎に実装する必要がある．本ドキュメントは，こ
れらの関数の外部仕様についてまとめたものである．また，テストプログラム
実行のために必要なマクロも本ドキュメントで定義する．

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
(2) 割込み発生関数
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

本章では，割込み発生関数の仕様について定義する．割込み発生関数は2種類あ
る．
・割込みの発生
・割込み要求のクリア

―――――――――――――――――――――――――――――――――――
(2.1) 割込みの発生
―――――――――――――――――――――――――――――――――――

【プロトタイプ】
  void AktspRaiseInterrupt(INTNO intno)

【引数】
  intno : 割込み番号

【戻り値】
  なし

【仕様】
  intnoで指定した割込み番号の割込みを発生させる．テストプログラムでは，
  本関数を実行した後に，カテゴリ1 ISRもしくはカテゴリ2 ISRが起動するこ
  とを確認してから処理を進めるため，本関数内で割込みが実際に発生するこ
  とを待つ必要はない．逆に，待つ実装としてはならない．これは多重割込み
  のテスト等で，高優先度のISRから低優先度のISRを発生させた際に，処理が
  停止するのを防ぐためである．

  マルチコアの場合，本関数を実行する処理単位が割り付けられているコアに，
  割込みを発生させるものとする．intnoに，他コアに接続された割込み番号を
  指定した場合は，無視する．

―――――――――――――――――――――――――――――――――――
(2.2) 割込み要求のクリア
―――――――――――――――――――――――――――――――――――

【プロトタイプ】
  void AktspClearIntRequest(INTNO intno)

【引数】
  intno : 割込み番号

【戻り値】
  なし

【仕様】
  intnoで指定した割込み発生時に，明示的に割込み要求をクリアする．
  ATK2の場合，割込みコントローラ上の割込み要求フラグクリアは，
  i_begin_intとi_end_intによりOSが行うが，ターゲットシステムによっては，
  タイマやシリアルなど，個々のデバイスに対する割込み要求のクリア処理が
  必要となる場合がある．このクリア処理を実装する．本処理が不要なターゲ
  ットシステムの場合，何も処理しない空のAktspClearIntRequestを定義する．
  ※テストプログラムでは，ISRの先頭で本関数を実行する

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
(3) プロテクションフック起動関数
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

本章では，プロテクションフック起動関数の仕様について定義する．プロテク
ションフック起動関数は2種類ある．

・プロテクションフック起動
・プロテクションフック初期処理

―――――――――――――――――――――――――――――――――――

―――――――――――――――――――――――――――――――――――

【プロトタイプ】
  void AktspRaiseProtectionHook(void)

【引数】
  なし

【戻り値】
  なし

【仕様】
  プロテクションフックを起動させる(例：CPU例外を発生させるなど)．ただし，
  プロテクションフックの返り値にPRO_IGNOREを指定可能な保護違反処理とす
  ること．
  ※テストプログラムでは，プロテクションフックで一律PRO_IGNOREを返す

―――――――――――――――――――――――――――――――――――
(3.2) プロテクションフック初期処理
―――――――――――――――――――――――――――――――――――

【プロトタイプ】
  void AktspProtectionHookInit(void)

【引数】
  なし

【戻り値】
  なし

【仕様】
  プロテクションフックの先頭で必要な処理などを実装する．
  処理が不要なターゲットシステムの場合，何も処理しない空の
  AktspProtectionHookInitを定義する．
  ※テストプログラムでは，プロテクションフックの先頭で本関数を実行する

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
(4) ハードウェアカウンタ操作関数
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

本章では，ハードウェアカウンタ操作関数の仕様について定義する．ハードウ
ェアカウンタ操作関数は4種類ある．
・ハードウェアカウンタのティック更新停止
・ハードウェアカウンタのティック更新開始
・ハードウェアカウンタのティック初期化
・ハードウェアカウンタのティック更新

ATK2でハードウェアカウンタを使用するには，上記4つの関数と同じ振る舞いを
する関数を用意する必要がある．そのため，ATK2の実装依存テストライブラリ
には，4つの関数が実装済みである．ただし，(4.4)は，テスト用の関数である
ため，用意されていない可能性がある．(4.4)が用意できないターゲットである
場合は，ATK2の実装依存テストライブラリに用意したダミーハードウェアカウ
ンタを利用して，テストを実施することが可能である．

―――――――――――――――――――――――――――――――――――
(4.1) ハードウェアカウンタのティック更新停止
―――――――――――――――――――――――――――――――――――

【プロトタイプ】
  StatusType AktspStopHardwareCounter(CounterType CounterID)

【引数】
  CounterID : ハードウェアカウンタのID

【戻り値】
  E_OK     : 正常終了
  E_NOT_OK : 異常終了

【役割】
  CounterIDで指定したハードウェアカウンタのティック更新を停止する．

―――――――――――――――――――――――――――――――――――
(4.2) ハードウェアカウンタのティック更新開始
―――――――――――――――――――――――――――――――――――

【プロトタイプ】
  StatusType AktspStartHardwareCounter(CounterType CounterID)

【引数】
  CounterID : ハードウェアカウンタのID

【戻り値】
  E_OK     : 正常終了
  E_NOT_OK : 異常終了

【役割】
  CounterIDで指定したハードウェアカウンタのティック更新を開始する．

―――――――――――――――――――――――――――――――――――
(4.3) ハードウェアカウンタのティック初期化
―――――――――――――――――――――――――――――――――――

【プロトタイプ】
  StatusType AktspInitHardwareCounter(CounterType CounterID)

【引数】
  CounterID : ハードウェアカウンタのID

【戻り値】
  E_OK     : 正常終了
  E_NOT_OK : 異常終了

【役割】
  CounterIDで指定したハードウェアカウンタのティックを0へ初期化し，設定
  済みの満了点が存在する場合は，クリアする．

―――――――――――――――――――――――――――――――――――
(4.4) ハードウェアカウンタのティック更新
―――――――――――――――――――――――――――――――――――

【プロトタイプ】
  StatusType AktspIncrementHardwareCounter(CounterType CounterID)

【引数】
  CounterID : ハードウェアカウンタのID

【戻り値】
  E_OK     : 正常終了
  E_NOT_OK : 異常終了

【役割】
  CounterIDで指定したハードウェアカウンタのティックを1加算する．加算し
  た結果，満了点に到達した場合，満了処理を実行する．

(5) スタックオーバーフロー発生関数
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

本章では，スタックオーバーフローを発生させるための関数の仕様について定
義する．スタックオーバーフロー発生関数は以下7種類の検出タイミングに対応
するものを用意する．
・タスク系システムサービス発行時
・割込み発生時
・多重割込み発生時
・割込みリターン時
・信頼関数リターン時(SC3，SC4のみ)
・コア間割込み発生時(MCのみ)
・コア間割込みによる多重割込み発生時(MCのみ)

―――――――――――――――――――――――――――――――――――
(5.1) タスク系システムサービス発行時
―――――――――――――――――――――――――――――――――――

【プロトタイプ】
  void AktspRaiseTaskStackOverflowByDispatch(uint8* stk, MemorySizeType size, const AktspStackOverflowRefInfo info)

【引数】
  stk      : スタックオーバーフローを発生させるタスクのスタック先頭番地
  size     : スタックオーバーフローを発生させるタスクのスタックサイズ
  info     : スタックオーバーフローに関する情報の構造体のポインタ
  
 【infoの概要】
  構造体データ型：AktspStackOverflowInfo

   データ型           | メンバ名     | 概要                                 | 凡例  | 備考
                      |              |                                      |       |
  ==========================================================================================
   uint8              | stk_mode     | スタックモニタリング方式種別         | ※1   |
  ------------------------------------------------------------------------------------------
   uint8              | stk_action   | スタックオーバーフロー検出アクション | ※2   |
  ------------------------------------------------------------------------------------------
   TaskType           | stk_task     | システムサービス発行対象タスク       |       |
  ------------------------------------------------------------------------------------------
   EventMaskType      | stk_event    | システムサービス発行対象イベント     |       |
  ------------------------------------------------------------------------------------------
   ResourceType       | stk_resource | システムサービス発行対象リソース     |       |
  ------------------------------------------------------------------------------------------
   IntrruptNumberType | stk_intno    | 発生させるISRの割込み番号            |       |
  ------------------------------------------------------------------------------------------
   ISRType            | stk_isrid    | 発生させるコア間割込みのISRID        |       |
  
  ※1 値                   | 意味
     --------------------------------------------------
      AK_SMM_MAGIC_NUMBER  | マジックナンバー方式
      AK_SMM_STACK_POINTER | スタックポインタ方式
      AK_SMM_CHECK_REMAIN  | スタック残量チェック方式

  ※2 値                      | 意味
     -----------------------------------------------
      AK_SOA_ACTIVATE_TASK    | ActivateTask
      AK_SOA_TERMINATE_TASK   | TerminateTask
      AK_SOA_CHAIN_TASK       | ChainTask
      AK_SOA_SCHEDULE         | Schedule
      AK_SOA_SET_EVENT        | etEvent
      AK_SOA_WAIT_EVENT       | WaitEvent
      AK_SOA_RELEASE_RESOURCE | ReleaseResource

【戻り値】
  なし

【仕様】
  ＜マジックナンバー方式＞
    スタックオーバーフローを発生するタスクのスタック領域が，stk，sizeで
    与えられるため，ターゲット依存で設定したマジックナンバー領域を書き
    換える．

  ＜スタックポインタ方式＞
    スタックオーバーフローを発生するタスクのスタック領域が，stk，sizeで
    与えられるため，ターゲット依存で実装したスタックポインタのチェック
    処理に違反するように，スタックポインタを変更する．AKTGが生成するテ
    ストプログラムでは，タスクのスタック領域の前に予備の領域を確保する
    ため，この領域へスタックポインタを変更することを推奨する．

  ＜共通処理＞
    各方式でスタックオーバーフローを検出する状態とした後で，stk_action
    で指定されたシステムサービスを，必要な引数を使用して発行する．本関
    数は，このシステムサービスによってディスパッチが発生する前提で呼び
    出すため，ディスパッチ発生時に，スタックオーバーフローを検出する．

―――――――――――――――――――――――――――――――――――
(5.2) 割込み発生時
―――――――――――――――――――――――――――――――――――

【プロトタイプ】
  void AktspRaiseTaskStackOverflowByInterrupt(uint8* stk, MemorySizeType size, const AktspStackOverflowRefInfo info)

【引数】
  stk   : スタックオーバーフローを発生させるタスクのスタック先頭番地
  size  : スタックオーバーフローを発生させるタスクのスタックサイズ
  info  : スタックオーバーフローに関する情報の構造体のポインタ
          (構造体の概要は(5.1)を参照)

【戻り値】
  なし

【仕様】
  ＜マジックナンバー方式＞
    (5.1)と同様．

  ＜スタックポインタ方式＞
    (5.1)と同様．

  ＜共通処理＞
    各方式でスタックオーバーフローを検出する状態とした後で，stk_intnoで
    指定された割込み番号の割込みを発生する．割込み発生時に，スタックオ
    ーバーフローを検出する．

―――――――――――――――――――――――――――――――――――
(5.3) 多重割込み発生時
―――――――――――――――――――――――――――――――――――

【プロトタイプ】
  void AktspRaiseIsrStackOverflowByInterrupt(uint8* stk, MemorySizeType size, const AktspStackOverflowRefInfo info)

【引数】
  stk   : スタックオーバーフローを発生させるISRのスタック先頭番地
  size  : スタックオーバーフローを発生させるISRのスタックサイズ
  info  : スタックオーバーフローに関する情報の構造体のポインタ
          (構造体の概要は(5.1)を参照)

【戻り値】
  なし

【仕様】
  ＜マジックナンバー方式＞
    スタックオーバーフローを発生するISRのスタック領域が，stk，sizeで与
    えられるため，ターゲット依存で設定したマジックナンバー領域を書き換
    える．

  ＜スタック残量チェック方式＞
    スタックオーバーフローを発生するISRの情報がinfoで与えられるため，
    ターゲット依存で実装したスタック残量チェック処理に違反するように，
    スタックポインタを変更する．

  ＜共通処理＞
    各方式でスタックオーバーフローを検出する状態とした後で，stk_intnoで
    指定された割込み番号の割込みを発生する．割込み発生時に，スタックオ
    ーバーフローを検出する．本関数は，ISR実行中に呼び出される前提のため，
    stk_intnoには実行中のISRより高い割込み優先度の割込み番号を指定する．

(5.4) 割込みリターン時
―――――――――――――――――――――――――――――――――――

【プロトタイプ】
  void AktspRaiseIsrStackOverflowByReturn(uint8* stk, MemorySizeType size)

【引数】
  stk   : スタックオーバーフローを発生させるISRのスタック先頭番地
  size  : スタックオーバーフローを発生させるISRのスタックサイズ

【戻り値】
  なし

【仕様】

  バーフローを検出するわけではない．

(7.1) メモリアクセス関数共通の引数
―――――――――――――――――――――――――――――――――――

以下5つの共通の引数がある．
service ：CheckTaskMemoryAccessおよびCheckISRMemoryAccessのシステムサ
          ービステストを実行する場合はtrueを指定する
tsk1id ：Task1(信頼OSAP1)のタスクID
         CheckTask(or ISR)MemoryAccessのテストにて使用する
         serviceがfalseの場合は，使用しない
tsk2id ：Task2(非信頼OSAP1)のタスクID

         CheckTask(or ISR)MemoryAccessのテストにて使用する
         serviceがfalseの場合は，使用しない

         serviceがfalseの場合は，使用しない

(7.2) すべてのOSAP，処理単位からアクセスできる領域へのアクセス
―――――――――――――――――――――――――――――――――――

【プロトタイプ】
  void AktspAccessAllAccessibleArea(boolean service, TaskType tsk1id, TaskType tsk2id, TaskType tsk3id, ISRType isrid)

【引数】
  (7.1)を参照

【戻り値】
  なし

【仕様】
  すべてのOSAP，処理単位からアクセスできる領域(共有領域)へのアクセスを
  実行する．
  メモリアクセスの方法は，以下の5つである．
  ・読出し(上限)：先頭アドレスのデータを読み出す
                  このパターンのみメモリアクセスを行う前に内部関数
                  AktspCheckMemoryAccessをコールする．
  ・読出し(下限)：終端アドレス(※1)のデータを読み出す
  ・書込み(上限)：先頭アドレスのデータに1を書き込む
  ・書込み(下限)：終端アドレス(※1)のデータに1を書き込む
  ・実行        ：領域に配置されている関数を実行する

  (※1)定義されている終端アドレスは次の領域の先頭アドレスとなっている
       ため，定義されている終端アドレスから1を引いたアドレスにアクセス
       する

―――――――――――――――――――――――――――――――――――
(7.3) 非信頼OSAP1からのみアクセスできない領域へのアクセス
―――――――――――――――――――――――――――――――――――

【プロトタイプ】
  void AktspAccessNtOsap1InaccessibleArea(boolean enable, uint16 action, boolean service, TaskType tsk1id, TaskType tsk2id, TaskType tsk3id, ISRType isrid)

【引数】
  enable  ：アクセス可否
  action  ：メモリ領域の種類，アクセス方法の指定番号
  service，Task1ID，Task2ID，Task3IDについては，(7.1)を参照

【戻り値】
  なし

【仕様】
  actionで指定されたメモリ領域に指定されたメモリアクセスを実行する(※1
  )．
  この関数でアクセスするメモリ領域は，非信頼OSAP1からのみアクセスできな
  い領域(非信頼OSAP2の専有領域)とする．
  メモリアクセス方法は，(7.1)と同様．
  また，enableがtrueの場合は，actionを0で固定し，この関数内で指定してい
  るすべての領域，メモリアクセスを実行する．

  (※1)actionがどの領域にどのようにアクセスするかは，別紙「
       memory_protection_poricy.xls」のシート「メモリアクセスパターン」
       を参照．

(7.8) メモリ保護テストのTESRYデータを展開するスクリプト
―――――――――――――――――――――――――――――――――――

(7.1)~(7.15)のメモリアクセスを実行する関数を(メモリ領域×メモリアクセ
ス)分を実行しなければならない．この部分はPictモデルファイルで記述するこ
とが困難なため(パターン数が多くなるためPictモデルファイルのパラメータと
して記述することが難しい)，メモリアクセス実行関数をテスト実行する回数分
展開するスクリプト(Ruby)を用意した．この節では，このスクリプトに関する
説明をする．

【ファイル名】
  convert_memory_protection_tesry.rb

【使用方法】
  TESRYファイルがあるディレクトリで，コマンドライン引数に設定ファイル(
  後述)を指定して実行する

  # scripts/convert_memory_protection_tesry.rb memcvt.yaml

【実行内容】
  (例)設定ファイル内容が「AktspNoAccessAllNonTrustedOsap: 105」の場合
  "AktspNoAccessAllNonTrustedOsap"が存在するyamlファイルについて以下の
  処理を行う．
  [1]元のファイルをコピーして"_XXXX"とつけてリネームする
  [2]リネームしたファイルのAktspNoAccessAllNonTrustedOsap関数の引数部分
     を置換
     "(xxx)"→"(XXXX)"
     設定ファイルから読み込んだ数値の回数分繰り返す
     XXXXは0から設定ファイルから読み込んだ数値-1(この例では104)まで変化

【設定ファイル】
  target/(ターゲット名)/memory_protection/memcvt.yaml

【設定ファイルの内容】
  関数: 実行する数
  ※コロンの後に，1つ以上半角スペースを入れること
  (記載例)
   AktspNoAccessAllNonTrustedOsap: 105
   AktspNoAccessNonTrustedOsap2: 35
   AktspNoAccessNonTrustedOsap1: 35
   AktspAccessAllProcessUnit: 55
   …

(8) ターゲット依存マクロ
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

本章では，定義が必要なターゲット依存マクロについて定義する．
定義が必要なマクロは，nios2_dev_gcc用のターゲット依存テストライブラリ
(aktsp/library/target/nios_dev_gcc)のaktsp_target_lib.hに定義し，
"AKTSP_"から始まるマクロとする．また，AKTGが生成するテストプログラム
(out.h)で定義するマクロは，"AKTG_"から始まるマクロとする．
C1ISR出入り口処理用のマクロ(カテゴリ1 ISR実行用マクロ)については，(8.1)
節を参照して作成する．

―――――――――――――――――――――――――――――――――――
(8.1) カテゴリ1 ISR実行用マクロ
―――――――――――――――――――――――――――――――――――

本節では，カテゴリ1 ISRの使用方法について定義する．
カテゴリ1 ISRは，C言語，アセンブラのどちらでも実装される可能性があるた
め，以下のマクロにより，両者に対応する．

【マクロ定義】
  #define AKTSP_C1ISR_ENTRY(C1ISRName, EntityFuncName)

【引数】
  C1ISRName      : コンフィギュレーション時に指定したISRID
  EntityFuncName : AKTGが生成するカテゴリ1 ISRの処理を実装したC言語の関数名

【仕様】
  カテゴリ1 ISRからの，システムサービスの呼び出しを可能にするため，レジ
  スタの保存/復帰，処理レベルの変更などを行う．コンフィギュレーション時
  にカテゴリ1 ISRを指定した場合に，OSがこれらの処理を実行する実装である
  場合は，本マクロは単にEntityFuncNameで与えられた関数を呼び出すだけで
  よい．

  (a)C言語の場合
    カテゴリ1 ISR(C1ISRName)マクロで変換される関数を，プロトタイプ宣言
    する．
    関数本体も，C言語で記述する．
    ※参考：at91skyeye_gcc依存部

  (b)アセンブラの場合
    カテゴリ1 ISR(C1ISRName)マクロで変換されるラベルを定義し，処理をア
    センブラで記述する．ただし，コンパイラによっては様々な実現方法があ
    る．
    ※参考：nios2_dev_gcc依存部

―――――――――――――――――――――――――――――――――――
(8.2) シングル/マルチコア共用で使用するスタックアドレス用マクロ
―――――――――――――――――――――――――――――――――――

本節では，シングルコア，マルチコアで共用で使用するタスクスタックアドレ
スのマクロについて定義する．
スタックは2次元配列で用意しており，1次元目がタスク毎の先頭番地となって
いる．メモリ保護テストではタスク毎の先頭番地の指定が必要なため，マクロ
で行う．スタック領域に関しては，(9)章を参照．

【マクロ定義】
 《信頼タスク用スタック》
  #define AKTSP_MEM_TR_TASK_STACK(task_no, pos) (aktg_stack[(task_no)][(pos)])       (シングルコア)
                                                (aktg_stack_core0[(task_no)][(pos)]) (マルチコア)

 《非信頼タスク用スタック》
  #define AKTSP_MEM_NT_TASK_STACK(task_no, pos) (aktg_ustack[(task_no)][(pos)])       (シングルコア)
                                                (aktg_ustack_core0[(task_no)][(pos)]) (マルチコア)

 《非信頼タスク用システムスタック》
  #define AKTSP_MEM_TASK_SYS_STACK(task_no, pos) (aktg_sstack[(task_no)][(pos)])       (シングルコア)
                                                 (aktg_sstack_core0[(task_no)][(pos)]) (マルチコア)

【引数】
  task_no : タスクの番号
  pos     : アドレス

―――――――――――――――――――――――――――――――――――
(8.3) マルチコアで使用するスタックアドレス用マクロ
―――――――――――――――――――――――――――――――――――

本節では，マルチコアで使用するOSスタック，タスクスタックアドレスのマク
ロについて定義する．マルチコアでは，コア毎にスタックを定義可能とするた
め，コア毎にスタックを定義する必要がある．そのため，コア毎にスタック領
域を分割できるよう，アドレス指定をマクロで行う．スタック領域に関しては，
(9.3)章を参照．

【マクロ定義】
 《OSスタックの場合》
  #define AKTG_OS_STACK_ADDRESS_CORE_0 (aktg_os_stack[0] + AKTSP_BUFFER_STACK_SIZE)
  #define AKTG_OS_STACK_ADDRESS_CORE_1 (aktg_os_stack[1] + AKTSP_BUFFER_STACK_SIZE)

 《信頼タスクスタックの場合》
  #define AKTG_TASK_STACK_ADDRESS_CORE_0(task_no) (aktg_stack_core0[(task_no)])
  #define AKTG_TASK_STACK_ADDRESS_CORE_1(task_no) (aktg_stack_core1[(task_no)])

 《システムスタックの場合》
  #define AKTG_TASK_SSTACK_ADDRESS_CORE_0(task_no) (aktg_sstack_core0[(task_no)])
  #define AKTG_TASK_SSTACK_ADDRESS_CORE_1(task_no) (aktg_sstack_core1[(task_no)])

 《非信頼タスクスタックの場合》
  #define AKTG_TASK_USTACK_ADDRESS_CORE_0(task_no) (aktg_ustack_core0[(task_no)])
  #define AKTG_TASK_USTACK_ADDRESS_CORE_1(task_no) (aktg_ustack_core1[(task_no)])

 【引数】
  task_no：タスクが定義されたコアにある全タスク中のタスクの番号

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
(9) スタック領域の確保
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

本章では，ATK2においてコンフィギュレーションにより，タスク間で使用する
スタックを共有できる機能を用いるための，スタック領域について定義する．
複数のテストケースをマージする場合，同一優先度の基本タスクのスタック領
域は，コンフィギュレーションによって自動的に共有されるが，拡張タスクの
スタック領域は共有されず，全テストに登場する拡張タスクの数だけスタック
領域が確保されるため，テスト件数によっては膨大なスタック領域が必要とな
ってしまう．そこでAKTGでは，基本タスク，拡張タスクに関わらず，1テストケ
ースに登場するタスクの最大数の数だけスタック領域を確保し，すべてのテス
トケースでこのスタック領域を使いまわす機能を用意している．スタックモニ
タリングのテストにおいては，このスタック領域に対して，意図的にスタック
オーバーフローを発生させることで実施する．
なお，OSAPの使用有無で必要なスタック領域の種類が変わるため，(8.1)節では
SC1，SC2の場合について，(8.2)節では，SC3，SC4の機能レベル2以下の場合に
ついてを記述する．

【共通仕様】
  スタックを共有する場合に使用する．スタックを共有する場合，AKTGが生成
  するテストプログラム(out.h)に，AKTG_USE_SHARE_STACKマクロが定義される．
  このマクロが定義されている場合にのみ，各節で定義するスタック領域を確
  保する．
  また，1テストケースに登場するタスクの最大数が，AKTG_STACK_NUMマクロで
  定義される．SC3，SC4では，AKTG_STACK_NUMマクロは信頼OSAPに所属するタ
  スクの最大数を意味し，AKTG_USTACK_NUMマクロが非信頼OSAPに所属するタス
  クの最大数を意味する．
  したがって，各節で定義するアドレスのスタック領域が，out.hでincludeす
  るaktsp_target_lib.hから参照できること．
  (ターゲットによってはout.hの名称が変更される場合がある)

―――――――――――――――――――――――――――――――――――
(9.1) SC1，SC2の場合
―――――――――――――――――――――――――――――――――――

本節では，テスト対象とするOSがSC1，SC2の場合のスタック領域について定義
する．

【仕様】

【名前(アドレス)】
  aktg_os_stack

【サイズ】
  AKTSP_OS_STACK_SIZE

【仕様】
  SC3，SC4(機能レベル2以下)では1つのみ用意する．
  .prsv_kernelセクションに確保する．
  またMCの場合は，コア毎にスタックを確保するため，以下の定義となる．
  aktg_os_stack[AKTG_CORE_NUM][AKTSP_OS_STACK_SIZE + AKTSP_BUFFER_STACK_SIZE]
  AKTG_CORE_NUMは，1テストケースに登場するコアの最大数であり，AKTGによ
  ってout.hに定義される．

(9.3) MC(機能レベル2以下)の場合
―――――――――――――――――――――――――――――――――――

本節では，テスト対象とするOSがMC(SC1-MC，SC2-MC，SC3-MC，SC4-MC)の場合
のスタック領域について定義する．本定義は一例であり，(8.2)節で示したマル
チコア用のマクロに適合するように，スタック領域およびマクロを確保すれば，
本定義に従う必要はない．

【SC3-MC，SC4-MC通仕様】
  スタックを確保するセクションとして，.prsv_kernelセクションと
  .stack_sectionセクションを作成する．

―――――――――――――――――――――――――――――――――――
(10.1) ターゲットに依存した初期化関数
―――――――――――――――――――――――――――――――――――

【プロトタイプ】
  void AktspInitializeTargetTestLib(void)

【引数】
  なし

【戻り値】
  なし

【仕様】
  ターゲットによって，OS起動前に実施するべき処理を行う．
  必要がなければ，空の関数を用意する．

―――――――――――――――――――――――――――――――――――
(10.2) マルチコア用のターゲットに依存した初期化関数
―――――――――――――――――――――――――――――――――――

【プロトタイプ】
  void AktspInitializeTargetTestLibEachCore(void)

【引数】
  なし

【戻り値】
  なし

【仕様】
  ターゲットによって，OS起動前に各コアでそれぞれ実施するべき処理を行う．
  AktspInitializeTargetTestLibはマスタコアでのみ呼び出され，
  AktspInitializeTargetTestLibEachCoreはマスタコアを含めたすべての
  コアで呼び出される．
  必要がなければ，空の関数を用意する．
