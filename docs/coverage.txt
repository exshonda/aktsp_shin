(1) はじめに
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

ソースコードカバレッジとは，テストプログラムによって，テスト対象とする
ソースコード中の実行されたパスを確認することで，網羅率を測定するもので
ある．AKTSPのテストプログラムによるソースコードカバレッジを確認すること
で，テストケース，テストプログラムの網羅性，妥当性を客観的に評価するこ
とが可能である．

なお，本ドキュメントは，AKTSP(Automotive Kernel Test Suite Package)およ
びAKTG(Automotive Kernel Test Generator)のユーザーズマニュアルの記載内
容を理解していることを前提とする．

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
(2) カバレッジ基準
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

一般に，ソースコードカバレッジには以下の基準がある．
※文献により呼称が異なることがあるので注意する

・命令網羅(C0)
  プログラムの全行を少なくとも一回はテストする．

・条件網羅(C1)
  プログラムの判定に含まれる全条件を少なくも一回はテストする．

・条件分岐網羅(C2)
  プログラムの判定に含まれる全条件の全組み合わせを少なくも一回はテスト
  する．

テストの網羅性が最も高いのはC2であるが，プログラムの規模が大きくなると，
現実的にC2を100%とすることは困難である．そこで，C1とC2の中間に位置する
MD/DCが提唱されている．MD/DCでは，C1に加えて複数条件のANDとORの記述ミス
を検出できる基準で，条件網羅を実施する．

【MD/DC】http://www.zipc.com/cesl/info/03.pdf

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
(3) AKTSPにおけるカバレッジ取得に対する要件
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

―――――――――――――――――――――――――――――――――――
(3.1) カーネルソースコードのカバレッジのみ取得する
―――――――――――――――――――――――――――――――――――

AKTSPのテストプログラムは，カーネルをテストするものであるので，テストプ
ログラムやテストライブラリのカバレッジは不要である．よって，テストプロ
グラム実行時に，カーネルのソースコードで実行されるパスのみを取得できれ
ばよい．また，特定のターゲット依存部のカバレッジを測定しても，他のター
ゲットでは意味を持たないことから，ターゲット非依存部のカバレッジを対象
とする．ATK2では，kernelフォルダ内のファイルを対象とする．

―――――――――――――――――――――――――――――――――――
(3.2) システムサービステストにおけるカバレッジ
―――――――――――――――――――――――――――――――――――

システムサービステストでは，ある特定の前状態において，テスト対象のシス
テムサービスを発行し，特定の後状態となることを確認するテストである．こ
のテストにおいて，カーネルソースコードのカバレッジを取得するべきポイン
トは，テスト対象のシステムサービス発行の部分だけである．これは，前状態
を準備するためのシステムサービス発行などで，パスしたカバレッジも，テス
トによるカバレッジに含めてしまうと，システムサービステストで設計したテ
ストケースのみで，カバレッジを網羅できたかの評価ができないためである．

―――――――――――――――――――――――――――――――――――
(3.3) 複数のテストプログラムによるカバレッジのマージ
―――――――――――――――――――――――――――――――――――

AKTSPではすべてのテストケースを，1つのテストプログラムで実施することが
できない．これは単にプログラムサイズ上の問題，ターゲットのメモリ制約，
シャットダウンを伴うテストの内容など，理由は多様である．したがって，
AKTSPを用いた全テストにおけるカバレッジを取得するには，複数のテストプロ
グラムを実行して取得したカバレッジをマージする必要がある．

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
(4) カバレッジ取得ツールの概要
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

―――――――――――――――――――――――――――――――――――
(4.1) GCOV
―――――――――――――――――――――――――――――――――――

GCCに付属しているカバレッジ取得ツールで，C1を取得することが可能である．
ATK2では，at91skyeye_gcc依存部に，GCOVを使用するためのライブラリ等を実
装済みである．なお，GCOVではMC/DCの取得はできない．

GCOVを取得する対象のオブジェクトファイルをコンパイルする際に，GCCに特定
のオプションを付与することで，カバレッジを出力するように設定できる．こ
れにより，カーネルオブジェクトにのみオプションを付与することで，(3.1)の
要件を満たすことができる．

システムサービステストのTESRYデータには，テスト対象のシステムサービスを
発行する箇所に，カバレッジ取得対象であることを示すフラグ(gcov)を付与し
ている．AKTGはこれを使用することで，--enable_gcovオプションにより，テス
トプログラムに以下の処理を追加する．
・テストプログラムの冒頭で，GCOVによるカバレッジ取得を中断する
・gcovフラグを参考に，テスト対象のシステムサービス発行前後で，
  GCOVによるカバレッジ取得の再開，中断を行うAPIを発行する
  ※カバレッジ取得の再開，中断を行うAPIはskyeye.exeを改造して実現した
・テストプログラムの最後に，GCOVによるカバレッジ情報を出力する
これにより(3.2)の要件を満たすことができる．
なお，gcovフラグに関係なく，すべてのカバレッジを取得する場合は，
--enable_gcovオプションを付与しなければよい．

ATK2では，カーネルをライブラリ提供するために，アプリケーションビルド時，
カーネルをライブラリから使用する機能を有している．複数のテストプログラ
ムのカバレッジをマージする場合，カーネルライブラリを共有することで，カ
ーネルの部分のみ，同一ファイルにカバレッジ情報を出力することが可能であ
る．これにより(3.3)の要件を満たすことができる．

ただし，カバレッジ取得の再開，中断を行うAPIは，skyeye.exeでのみ実行でき
るため，他のターゲットの実行はできない．また，カバレッジ取得の再開，中
断を行わないとしても，GCCを使用するターゲット毎に，カバレッジ情報をファ
イルへ出力する処理の実装が必要である．

―――――――――――――――――――――――――――――――――――
(4.2) C++test
―――――――――――――――――――――――――――――――――――

Parasoft社製のテストツールであるC++testを使用することで，MC/DCの取得が
可能である．テクマトリックス株式会社が日本で唯一の代理店であり，保守サ
ポートも実施している．

C++testでは，テスト対象のソースコードに独自のタグを埋め込み，カバレッジ
情報を取得する．ATK2では，あらゆるターゲットがsyslog機能によってコンソ
ール上にログを出力できることが期待されるため，カバレッジ情報はsyslogに
より，コンソールに出力するように実装した．これをダンプすることで，カバ
レッジ情報を取得することができる．

C++testでカバレッジ用のタグを付与するソースファイルを指定できるので，
これをカーネルのみとすることで，(3.1)の要件を満たすことができる．

C++testでは，カバレッジの取得有無を切り替えるAPIが用意されているので，
GCOV同様，gcovフラグを参考に，テスト対象のシステムサービス発行前後で，
カバレッジ取得の再開，中断を行うことができる．AKTGでは，
--enable_cpptestオプションにより，テストプログラムに以下の処理を追加す
る．
・C++testテスト用APIをextern宣言する
・C++testテスト用初期化APIをmain関数で実行する
・gcovフラグを参考に，テスト対象のシステムサービス発行前後で，
  カバレッジの取得有無を切り替えるAPIを実行する
・テストプログラムの最後に，タグ付けされたソースコードに追加された
  カバレッジ情報表示APIを実行する
これにより(3.2)の要件を満たすことができる．
なお，gcovフラグに関係なく，すべてのカバレッジを取得する場合は，
--enable_cpptestオプションを付与せずに，カバレッジを取得すればよい．

C++testでは，カバレッジ情報をテキストファイルレベルでマージできるため，
複数のテストプログラムによるカバレッジ情報をマージすることができる．
これにより(3.3)の要件を満たすことができる．

(5) カバレッジ取得手順
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

本手順の前提として，ATK2およびAKTSPによるテスト実施方法を熟知しているも
のとする．

―――――――――――――――――――――――――――――――――――
(5.1) GCOV
―――――――――――――――――――――――――――――――――――

前述の通り，GCOVによるカバレッジ取得は，現状SkeEyeのみでサポートしてい
る．ATK2のSkyeEye依存部には，GCOV取得用のライブラリが用意されているため，
これを使用して，AKTSPによるテストにおけるC1カバレッジを取得可能である．
また，LCOVというツールによってGCOVで取得したカバレッジ情報を，htmlが可
視化することが可能である．

----------------------------------------------------------------------
(5.1.1) LCOVインストール
----------------------------------------------------------------------
lcov-1.9_patch.tar.gzを任意のディレクトリへ展開し，インストールする．
$ tar xvfz lcov-1.9_patch.tar.gz
$ cd lcov-1.9
$ make install

※lcov-1.9_patch.tar.gzは，AKTSPのtools/coverage以下に同梱している．

※cygwinにて，
  $ lcov -v
  と入力し，バージョンが返ってくればOK．

----------------------------------------------------------------------
(5.1.2) Makefile修正
----------------------------------------------------------------------
(1)テスト対象とするカーネルのsample以下にあるMakefileに対して，
   "ENABLE_TRACE"定義の後に以下のパラメータを追加する．
     ENABLE_GCOV = only_kernel_full
   もしくはテスト対象のシステムサービスの発行箇所のみのカバレッジを取得
   する場合は，以下のパラメータを追加する．
     ENABLE_GCOV = only_kernel_part

   ※パラメータの意味はtarget_user.txt参照．

(2)最適化を外す．
   (修正前) COPTS := $(COPTS) -O2
   (修正後) COPTS := $(COPTS) -O0

----------------------------------------------------------------------
(5.1.3) AKTGへのオプション付与
----------------------------------------------------------------------
ENABLE_GCOVにonly_kernel_partを指定した場合は，システムサービスの発行箇
所の前後で，カバレッジファイルの再開，中断等を行うテストプログラムを生
成するために，AKTG実行時に以下のオプションを付与する．

$ aktg.rb --enable_gcov true ***.yaml

----------------------------------------------------------------------
(5.1.4) ビルド＆実行
----------------------------------------------------------------------
テストプログラムをビルドして実行する．

※*.gcnoファイルがカバレッジ情報を生成するためのファイルで，実行によって
  生成される*.gcdaファイルがカバレッジ情報を保持するファイルである．

----------------------------------------------------------------------
(5.1.5) カバレッジファイル生成
----------------------------------------------------------------------
以下のコマンドにより，LCOVによるhtml形式でGUI化したカバレッジを取得する．
$ make lcov
→coverage_htmlディレクトリが生成される．
  coverage_html内のindex.htmlからカバレッジを確認する．

なお，LCOVを使用しなくても，以下のコマンドでテキスト形式でカバレッジ情
報を生成することが可能である．
$ arm-none-eabi-gcov.exe -a -b -c XXX.gcda
  XXX.gcda：カバレッジを取得したいファイル名
  →XXX.gcovファイルが生成される．

(6) AKTSPによる自動化
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

―――――――――――――――――――――――――――――――――――
(6.1) GCOV
―――――――――――――――――――――――――――――――――――

AKTBにより，分割したテストプログラムのカバレッジをマージする処理を，自動
化することが可能である．

----------------------------------------------------------------------
(6.1.1) AKTB環境設定ファイル(configure.sh)の修正
----------------------------------------------------------------------
(1)カーネルライブラリを使用する設定とする．
   USE_KERNEL_LIB="false"

これにより，エラーフックやプロテクションフックなどのすべてのコンフィギ
ュレーションが常にONとなった状態で，カーネルをビルドして，カーネルライ
ブラリを作成し，AKTGで生成するテストプログラムもすべてのコンフィギュレ
ーションをONとして定義される．

----------------------------------------------------------------------
(6.1.2) AKTBターゲット依存設定ファイル(aktsp_target.sh)の修正
----------------------------------------------------------------------
(1)AKTGへの追加オプションを設定する．
AKTG_OPT="--enable_gcov true"

(2)実行モジュールの実行処理を変更する．
カーネルライブラリ(libkernel.a)は，aktsp/kernel_lib以下に作成される．し
たがってこのlibkernel.aに対するカバレッジ情報はaktsp/kernel_lib以下に生
成される．つまり，分割してビルドした各テストプログラムも，aktsp/
kernel_lib以下に移動した上で実行することで，aktsp/kernel_lib以下に全テ
ストプログラムをマージしたカバレッジ情報を生成することができる．AKTBで
は，ターゲット毎に実行する処理を実装することができるため，以下のように，
各テストプログラムをaktsp/kernel_lib以下にコピーしてからの実行を繰り返
すことで自動化が可能である．

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
simulation()
{
	# skyeyeの定義
	MODULE_NAME="atk2-sc1.exe"
	SKYEYE_EXE="skyeye.exe"
	SKYEYE_CONF="../target/at91skyeye_gcc/skyeye.conf"

	# エラーメッセージ
	ERR_SKYEYE_PATH="Need to pass a path to skyeye"


	which $SKYEYE_EXE &> /dev/null
	if [ $? -eq 1 ]
	then
		echo "$ERR_SKYEYE_PATH"
		return
	fi
	check_file_name=$MODULE_NAME
	check_file
	if [ $? -eq 1 ]
	then
		return
	fi

	skyeye_conf="$AKTSP_DIR/$SKYEYE_CONF"

	cur=`pwd`
	pwd
	cp -p ./$MODULE_NAME $AKTSP_DIR/$KERNEL_LIB/
	cd $AKTSP_DIR/$KERNEL_LIB
	pwd

	create_log_file
	script -c "$SKYEYE_EXE -c $skyeye_conf -e $MODULE_NAME" -a $RESULT_EXECUTE
	sed -i "s/\r\r\n/\r\n/g" $RESULT_EXECUTE

	cd $cur
}
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

----------------------------------------------------------------------
(6.1.3) AKTBによるテストの実行
----------------------------------------------------------------------
AKTBによりカバレッジを取得したいテストを実行する．
※実行中，マージする際にwarningが出力されることがあるがカバレッジ取得対
  象のファイルに対するwarningでなければ問題ない．

----------------------------------------------------------------------
(6.1.4) カバレッジファイル生成
----------------------------------------------------------------------
LCOVによるhtml形式でGUI化したカバレッジを取得する．
aktsp/kernel_lib/に移動し，以下を実行する．
$ make lcov
→coverage_htmlディレクトリが生成される．
  coverage_html内のindex.htmlからカバレッジを確認する．
