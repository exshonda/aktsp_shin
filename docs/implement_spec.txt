(1) はじめに
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

AKTGが生成するテストプログラムは，TESRYデータのpre_condition，
post_conditionに記載されている状態が各OSオブジェクトの状態と一致してい
ることを判定および確認する．また，テストプログラムが意図した順序で実行
されているかの確認も行う．確認に使用するAPIとして，以下を定義する．
・ログ出力API
・エラー処理API
・状態確認API
・全割込み禁止状態取得API
さらに，テスト実行のために必要な以下のAPIについても定義する．
・エラーフック起動API
・信頼関数と信頼関数へのラッパー関数
これらのAPIは，対象とするOSの実装にあわせて作成する必要がある．本ドキュ
メントは，これらのAPIの外部仕様についてまとめたものである．また，テスト
プログラム実行のために必要なマクロも本ドキュメントで定義する．

なお，本ドキュメントで定義する各APIのプロトタイプ宣言は，
共通部分のaktsp_common_lib.hで定義済みであるため，実装のみを行えばよい．

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
(2) ログ出力API
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

ログ出力APIは，テストの成功/失敗や，エラー要因等を表示するためのAPIであ
る．ログ出力APIとして，書式付き出力を使用し，書式指定子の数によって4つ
のAPIを用意する．引数には，ポインタを格納できる符号付き整数として
intptr_t型を使用する．コンパイラがC99に準拠していない場合は，intptr_t型
に相当する型をOSで用意する．

(3.1) 条件チェックのエラー処理
―――――――――――――――――――――――――――――――――――

本APIは，テストライブラリの共通部分の，CheckAssert(exp)のマクロ置換後の
一部分である．

【プロトタイプ】
  void _CheckAssert(const char *expr, const char *file, sint32 line)

【引数】
  expr : 条件チェックの条件式
  file : 条件チェックしたファイルのファイル名
  line : 条件チェックしたファイルの行数

【戻り値】
  なし

【仕様】
  以下の処理を順に実施する．
  1) デバッグがしやすいよう，引数に与えられた内容をログ出力APIを用いて
     表示する
  2) グローバル変数cp_stateにAK_FALSEを代入する
  3) AktspShutdownOS()を呼出す

―――――――――――――――――――――――――――――――――――

【引数】
  ercd : エラーコードチェックした際に，OSが返したエラーコード
  file : 条件チェックしたファイルのファイル名
  line : 条件チェックしたファイルの行数

【戻り値】
  なし

  1) デバッグがしやすいよう，引数に与えられた内容をログ出力APIを用いて

  3) AktspShutdownOS()を呼出す

(4) 状態確認API
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

状態確認APIは，OSオブジェクトの内部状態を取得するためのAPIである．本
APIはTESRYデータの記載内容とOSオブジェクトの状態が一致しているかを判定
するために用いられる．

―――――――――――――――――――――――――――――――――――
(4.1) 全状態確認API共通の仕様
―――――――――――――――――――――――――――――――――――

・AKTGが出力するテストプログラムから呼び出され，OS内部状態とTESRYデータ
  に記載された状態が一致しているかを確認する
・全処理単位で使用可能とする
  ただし，AKTGが生成するテストプログラムにおいては，スタートアップフッ
  ク，シャットダウンフックでは呼ばれないこととする
・戻り値は，E_OK(正常終了)/E_NOT_OK(異常終了)とする
・状態確認APIが異常を返した場合，テストプログラムはOSを終了する

【制限事項】
・実装方法により，状態の確認ができない場合や，確認を行う必要のない場合
  は，何も処理を行わずにE_OKを返すこと
・OSの実装に依存している内部表現の値は，状態確認APIが本ドキュメントで指
  定されたデータ型へ変換し，比較を行うこと
・異常箇所が分かるように，エラーログを出力したい場合は，(2)ログ出力API
  を使用すること

―――――――――――――――――――――――――――――――――――
(4.2) 各状態確認APIの仕様
―――――――――――――――――――――――――――――――――――

本節では，各オブジェクトの状態確認APIの使用を規定する．

(4.2.1) タスク
----------------------------------------------------------------------

【プロトタイプ】
  StatusType AktspVerifyTask(TaskType TaskID, const AktspTaskRefInfo TaskInfo)

【引数】
  TaskID   : 確認対象のタスクID
  TaskInfo : 確認対象のタスク情報の構造体のポインタ

【仕様】
  TaskIDで指定したタスク情報を参照し，TaskInfoが指す構造体に格納されて
  いる情報が正しい場合はE_OKを返し，それ以外はE_NOT_OKを返す．

【引数】
  TaskID : 確認対象のタスクID
  ResID  : 確認対象のリソースID

【仕様】

  ※TESRYデータ用パラメータ一覧(param.txt)に記述されたTASKのrelresを確
    認するためのAPIである

(4.2.6) タスクにアクセス可能な非信頼OSAP
----------------------------------------------------------------------

【引数】

  ※マルチコアの場合，本APIを発行したコアの割込み禁止状態を確認する

                  |                |                                          | AK_ENABLE  : 許可状態 |             |
  ------------------------------------------------------------------------------------------------------------------------------
   uint8          | ism_susallint  | SuspendAllInterruptsによる割込み禁止状態 | AK_DISABLE : 禁止状態 | istat       | ※1 ※2
                  |                |                                          | AK_ENABLE  : 許可状態 |             |
  ------------------------------------------------------------------------------------------------------------------------------
   uint8          | ism_susosint32 | SuspendOSInterruptsによる割込み禁止状態  | AK_DISABLE : 禁止状態 | istat       | ※1 ※2

   -----------------------------------------------------------------------------------------------------------------------------
   uint8          | ism_susallcnt  | SuspendAllInterruptsのネスト回数         | >= 0                  |             | ※3
  ------------------------------------------------------------------------------------------------------------------------------
   uint8          | ism_susoscnt   | SuspendOSInterruptsのネスト回数          | >= 0                  |             | ※3

   ※1 TESRYデータのistatに記述された，割込み禁止状態(AK_DIS_ALL_INT，
       AK_SUS_ALL_INT，AK_SUS_OS_INT)をシステムサービスに分けて確認する
   ※2 TESRYデータのistatに何も記述されていない場合は，すべてAK_ENABLE
       であることを確認する
   ※3 TESRYデータのistatに記述された，割込み禁止状態(AK_SUS_ALL_INT，
       AK_SUS_OS_INT)のネスト回数を確認する

(4.2.16) 割込み禁止操作の順番
----------------------------------------------------------------------

【プロトタイプ】
  StatusType AktspVerifyDisIntOrder(uint32 Index, uint8 State)

【引数】
  Index : 割込み禁止状態を操作した順番
  State : Indexで指定した割込み禁止状態

【仕様】
  Indexで指定した順番の割込み禁止操作の状態が，Stateと一致している場合
  はE_OKを返し，以下の場合はE_NOT_OKを返す．
  ・Indexが割込み禁止のネスト総数より大きい
  ・Indexが0より小さい
  ・Stateが不一致
  ※AktspVerifyIntStateにおけるsus_all_cntとsus_os_cntの合計値が2以上
    の場合のみ，テストプログラムは本APIを使用する
  ※AK_DIS_ALL_INTはネストできないため，本APIでの確認は行うことはない
  ※StateにはAK_SUS_ALL_INT，AK_SUS_OS_INTのどちらが格納される
  ※マルチコアの場合，本APIを発行したコアの割込み禁止状態を確認する
  ※Indexは，SuspendAllInterruptsによる割込み禁止状態と
    SuspendOSInterruptsによる割込み禁止状態を区別せずに，下記の【テスト
    プログラムでの使用例】のように付与する

【テストプログラムでの使用例】
  ercd = AktspVerifyDisIntOrder(1, AK_SUS_ALL_INT);
  CheckAssert(ercd == E_OK);
  ercd = AktspVerifyDisIntOrder(2, AK_SUS_OS_INT);
  CheckAssert(ercd == E_OK);
  ercd = AktspVerifyDisIntOrder(3, AK_SUS_ALL_INT);
  CheckAssert(ercd == E_OK);
  ercd = AktspVerifyDisIntOrder(4, AK_SUS_OS_INT);
  CheckAssert(ercd == E_OK);

  構造体データ型：AktspIcISRRefInfo

   データ型        | メンバ名        | 概要                 | 凡例                   | TESRYデータ | 備考
                   |                 |                      |                        | (ICISR)     |
  ===========================================================================================================
   uint32          | icm_intatr      | 割込み属性           |                        | intatr      | ※3
  ----------------------------------------------------------------------------------------------------------
   uint8           | icm_istat       | 割込み要求禁止フラグ |                        | istat       | ※3
  ----------------------------------------------------------------------------------------------------------
   uint8           | icm_rtnstat     | 処理単位動作状態     | AK_ACTIVATE : 実行状態 | rtnstat     |
                   |                 |                      | AK_STOP     : 停止状態 |             |
  ----------------------------------------------------------------------------------------------------------
   uint32          | icm_getrescount | 取得済みリソース数   | >= 0                   |             | ※1
  ----------------------------------------------------------------------------------------------------------
   ApplicationType | icm_osap        | 所属するOSAP         |                        | osap        | ※3
  ----------------------------------------------------------------------------------------------------------
   MemorySizeType  | icm_istksz      | スタック領域のサイズ | >= 0                   | istksz      |
  ----------------------------------------------------------------------------------------------------------
   CoreType        | icm_coreid      | コアID               |                        | coreid      | ※2

  ※1 TESRYデータのgetresに記述された，リソースの数を確認する
  ※2 CoreTypeは，マルチコアかつNOS仕様の場合のみ使用する
  ※3 スケーラビリティクラスがSC3，SC4の場合，確認を行う

(5) 全割込み禁止状態取得API
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

全割込み禁止状態取得APIは，全割込み禁止状態であるかないかを取得するため
のAPIである．本APIは，テストライブラリの共通部分のAPI中で，
SuspendAllInterruptsを発行する際の判断に使用する．

【プロトタイプ】
  StatusType AktspGetDisableAllInterruptsState(void)

【引数】
  なし

【戻り値】
  AK_ON  : 全割込み禁止状態である
  AK_OFF : 全割込み禁止状態でない

【仕様】
  本APIを発行したコアが，全割込み禁止状態であるかないかを確認する．全割
  込み禁止状態であればAK_ONを返し，全割込み禁止状態でなければAK_OFFを返
  す．
  全割込み禁止状態が判断できない場合は，AK_ONを返す．ただし，全割込み禁
  止状態であるとみなし，本APIを使用するAPIの中で，SuspendAllInterrupts
  を発行せずに処理を行うため，その間の処理は保証されない．

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

(7) 信頼関数と信頼関数へのラッパー関数 ※SC3，SC4限定
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

本節では，SC3，SC4のテストプログラムで使用する信頼関数および，信頼関数
へのラッパー関数について規定する．SC3，SC4では，非信頼OSAPに所属するタ
スクやC2ISRは，他のOSAPに所属するオブジェクトに対してアクセス権が無く，
ShutdownOSを呼出すことができない．そのため，非信頼OSAPに所属するタスク
やC2ISRが実行状態の場合の，前状態作成や異常時のシャットダウンができるよ
う，以下の3種類の信頼関数と各信頼関数へのラッパー関数を作成する．

・前状態生成用信頼関数(タスクの起動)
・前状態生成用信頼関数(イベントのセット)
・異常時シャットダウン用信頼関数

なお，信頼関数のパラメータ用の構造体として，AktspTfParam(下記)を用意し
ている．

typedef struct aktsp_tf_param {
	TaskType		TaskID;
	EventMaskType	Mask;
	StatusType		Error;
} AktspTfParam;

(7.1) 前状態生成用信頼関数(タスクの起動)
―――――――――――――――――――――――――――――――――――

  StatusType TRUSTED_AktspTfnActivateTask(TrustedFunctionIndexType FunctionIndex, TrustedFunctionParameterRefType FunctionParams)
  <信頼関数が戻り値を返さない場合(AUTOSAR仕様)>
  void TRUSTED_AktspTfnActivateTask(TrustedFunctionIndexType FunctionIndex, TrustedFunctionParameterRefType FunctionParams)

【引数】
  FunctionIndex  : 信頼関数ID
  FunctionParams : 起動するタスクのタスクIDを格納する構造体のポインタ

【戻り値】
  <信頼関数が戻り値を返す場合(NCES独自仕様)>
  ActivateTaskの戻り値
  <信頼関数が戻り値を返さない場合(AUTOSAR仕様)>
  なし

【仕様】
  FunctionParamsに格納されたTaskIDのタスクを起動する．

(8) 実装依存マクロ
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

本章では，定義が必要な実装依存マクロについて定義する．定義が必要なマク
ロは，タスクの関数ポインタとアラームコールバックの関数ポインタである．

―――――――――――――――――――――――――――――――――――
(8.1) タスクの関数ポインタ
―――――――――――――――――――――――――――――――――――

CheckTaskMemoryAccessのテストでは，タスクのメインルーチンの先頭アドレス
を指定するために，TASKNAME(TASKName)を用いる．そのため，テスト対象のOS
に合わせるためにマクロを用いて変換する．

例) #define TASKNAME(TASKName) TASKMain ## TASKName

―――――――――――――――――――――――――――――――――――
(8.2) アラームコールバックの関数ポインタ
―――――――――――――――――――――――――――――――――――

AKTGが生成するテストプログラムでは，アラームコールバックの確認として
ALARMCALLBACKNAME(AlarmCallbackRoutineName)を状態確認APIに渡す．そのた
め，テスト対象のOSに合わせるためにマクロを用いて変換する．

例) #define ALARMCALLBACKNAME(AlarmCallbackRoutineName) ALARMCALLBACKROUTINE(AlarmCallbackRoutineName)
